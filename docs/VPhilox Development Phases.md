Here is the complete operational roadmap divided into 5 execution phases. Each phase defines specific deliverables, tests, and hardware mechanics to build and publish **vphilox**.

### **Phase 1: Foundation & Reference Scalar Engine**

**Goal:** Build a zero-dependency C++ scalar implementation of Philox4x32-10 to establish ground-truth outputs, tests, and benchmarking baselines.  
**Tasks:**

> 1. **Repository Setup:**  
   * Create vphilox/ with CMake target vphilox.  
   * Configure LICENSE-MIT and LICENSE-APACHE.  
> 2. **Scalar Implementation:**  
   * Write kernel\_scalar.hpp implementing Philox4x32-10 using explicit 64-bit integer casts for wide multiplication:  
     $$\\text{prod} \= (\\text{uint64\\\_t})R \\times M$$  
     $$\\text{hi} \= \\text{prod} \\gg 32, \\quad \\text{lo} \= (\\text{uint32\\\_t})\\text{prod}$$  
> 3. **Reference Parity Verification:**  
   * Add Google Test to compare your outputs against reference vectors from the original **Random123** paper (Salmon et al., 2011).  
> 4. **Baseline Micro-Benchmarking:**  
   * Measure scalar Philox throughput ($GB/s$ and CPU cycles/byte) against std::mt19937 in Google Benchmark.

**Deliverable:** A fully passing scalar baseline confirming $10\\times$ CPU degradation versus std::mt19937.

### **Phase 2: AVX2 / AVX-512 SIMD Kernel Development**

**Goal:** Eliminate the scalar multiply bottleneck by vectorizing 4 to 8 parallel Philox counters across SIMD vector lanes.  
**Tasks:**

> 1. **AVX2 Vector Interleaving (kernel\_avx2.hpp):**  
   * Load 4 128-bit counters into two 256-bit AVX2 registers (\_\_m256i).  
   * Execute \_mm256\_mul\_epu32 to evaluate 4 $32 \\times 32 \\to 64$-bit wide multiplies in a single CPU instruction cycle.  
   * Implement vector bit-shifts (\_mm256\_srli\_epi64), register shuffles (\_mm256\_shuffle\_epi32), and vector XORs (\_mm256\_xor\_si256) to execute 10 rounds.  
> 2. **ARM NEON Portability (kernel\_neon.hpp):**  
   * Map wide multiplies to ARM 64-bit architecture using vmull\_u32 for Apple Silicon / AWS Graviton platforms.  
> 3. **AVX-512 Interleaving (kernel\_avx512.hpp):**  
   * Scale register width to 512-bit (\_\_m512i) evaluating **8 parallel counters concurrently**.  
> 4. **SIMD Output Equality Test:**  
   * Verify that evaluating counters $C\_0 \\dots C\_3$ in SIMD produces bit-for-bit identical results to evaluating them sequentially in scalar code.

**Deliverable:** AVX2/AVX-512/NEON kernels outperforming std::mt19937 in single-threaded throughput.

### **Phase 3: Fast Floating-Point Conversion & C++20 Interface**

**Goal:** Add single-cycle integer-to-float transformation and wrap the SIMD core into a standard C++20-compliant class.  
**Tasks:**

> 1. **SIMD IEEE-754 Float Casting:**  
   * Implement bitwise mantissa injection:  
     $$\\text{float\\\_bits} \= \\texttt{0x3F800000} \\mid (\\text{rand\\\_u32} \\gg 9)$$  
     $$\\text{result\\\_float} \= \\text{cast\\\_to\\\_float}(\\text{float\\\_bits}) \- 1.0\\text{f}$$  
   * Evaluate vector float generation (vpor \+ vsubps) versus std::uniform\_real\_distribution division.  
> 2. **C++20 Concept Wrapper (philox.hpp):**  
   * Wrap SIMD generators inside a class fulfilling std::uniform\_random\_bit\_generator.  
   * Build a 32-byte or 64-byte aligned ring buffer to cache SIMD output blocks and serve scalar operator() calls in $O(1)$ time.  
> 3. **Runtime CPU Dispatch:**  
   * Add automatic CPU feature detection (\_\_builtin\_cpu\_supports("avx2")) to pick the fastest execution kernel dynamically at runtime if compile-time flags aren't set.

**Deliverable:** A header-only C++20 library usable directly with standard library algorithms (std::shuffle).

### **Phase 4: Empirical Benchmarking & Statistical Testing**

**Goal:** Generate empirical proof that vphilox passes rigorous statistical randomness tests while delivering top-tier performance.  
**Tasks:**

> 1. **PractRand / TestU01 Testing:**  
   * Stream gigabytes of generated bytes directly into the **PractRand** test suite pipe (./bench\_stream | rng\_test stdin).  
   * Confirm pass status through 1TB+ of generated random data (verifying no statistical flaws or low-byte biases).  
> 2. **Comprehensive Throughput Metrics:**  
   * Measure throughput across thread pools (1, 4, 8, 16, 32 threads) using OpenMP.  
   * Collect detailed CPU metrics: $GB/s$, CPU cycles per byte ($cpb$), and instruction cache miss rates.  
> 3. **Comparative Analysis Matrix:**  
   * Benchmark vphilox against: std::mt19937, scalar Philox4x32, xoshiro256++, and PCG64.

**Deliverable:** Complete benchmark dataset and statistical pass logs.

### **Phase 5: Paper Drafting & Release**

**Goal:** Publish the open-source repository and write a short technical research paper summarizing the SIMD vectorization architecture and empirical results.  
**Tasks:**

> 1. **Paper Composition (LaTeX / ACM Template):**  
   * **Title:** *vPhilox: SIMD-Accelerated Counter-Based Pseudo-Random Number Generation for Parallel CPU Systems*.  
   * Document the scalar wide-multiply bottleneck, AVX2/AVX-512 lane interleaving theory, and IEEE-754 mantissa injection math.  
   * Insert benchmark throughput graphs ($GB/s$ comparisons across vector widths).  
> 2. **Preprint & Citation Setup:**  
   * Upload paper to **arXiv** (Computer Science \- Performance / Mathematical Software).  
   * Register repository DOI via Zenodo.  
> 3. **Open-Source Release:**  
   * Publish GitHub repo sinhaparth5/vphilox.  
   * Include standard CITATION.cff file enabling one-click BibTeX citations.
