# AVX2 kernel — 2026-08-23

First measurement of a real SIMD backend. `detail/kernel_avx2.hpp` replaced its
scalar fallthrough with the eight-counter interleaved layout selected in issue
#12, closing issues #17–#23.

## Environment

| | |
|---|---|
| CPU | Intel Core i5-11300H (Tiger Lake), 4 cores / 8 threads |
| ISA | AVX2, AVX-512F/DQ (AVX-512 kernel still unimplemented) |
| OS | Linux 7.0.0-30-generic |
| Compiler | GCC 15.2.0, `bench` preset (`-O3`, Release) |
| Affinity | CPU 3 (`taskset -c 3`) |
| Frequency scaling | `powersave` governor, turbo enabled |

Fifteen repetitions at a two-second minimum sample time; the table reports
medians. Serialized `RDTSC` supplied the cycles-per-byte figure. Every
coefficient of variation came in under 1.5%.

The governor could not be pinned on this host, so these numbers carry the same
caveat as the lane-layout run: `RDTSC` counts at the nominal TSC rate rather
than the actual core clock, which makes cycles-per-byte a comparison between
rows of the same run rather than an absolute figure. All rows below were
measured back to back in one process, so the ratios are sound.

| Benchmark | Throughput | Cycles/byte | CV |
|---|---:|---:|---:|
| `BM_vphilox` (buffered engine, AVX2) | 2.352 GiB/s | 1.232 | 0.86% |
| `BM_vphilox_bulk` (AVX2 kernel) | 4.047 GiB/s | 0.716 | 0.65% |
| `BM_mt19937` | 1.673 GiB/s | 1.732 | 1.42% |
| `BM_philox_scalar` | 1.296 GiB/s | 2.235 | 0.67% |

Pinning the backend with `VPHILOX_BACKEND=scalar` on the same host gives the
before/after pair directly:

| Path | scalar | AVX2 | Speedup |
|---|---:|---:|---:|
| Bulk kernel | 1.226 GiB/s | 4.047 GiB/s | 3.30x |
| Bulk cycles/byte | 2.363 | 0.716 | 3.30x |
| Buffered engine | 1.099 GiB/s | 2.352 GiB/s | 2.14x |
| Buffered cycles/byte | 2.636 | 1.232 | 2.14x |

## Reading

**The Phase 2 deliverable is met for AVX2.** The buffered engine — what a user
actually calls — runs at 1.41x the throughput of `std::mt19937` and uses 0.71x
the cycles per byte. Before this change it ran at 0.65x of `mt19937`.

**The kernel itself is 3.3x the scalar kernel**, against a theoretical ceiling
of 8x from the lane count. The gap is the split wide multiply: `_mm256_mul_epu32`
only multiplies the low half of each 64-bit lane, so eight counters need two
multiplies plus a blend to repack, and the round body runs roughly 24 vector
operations where the scalar body runs about 10 scalar ones per counter.

**The buffer is now the dominant overhead.** Draining the refill buffer one
word at a time costs 41.9% of bulk throughput on AVX2, up from 10.4% on scalar
— the kernel got 3.3x faster while the per-word drain did not move at all.
That makes issue #36 substantially more valuable than its earlier ~22% estimate
suggested, and it is the reason `BM_vphilox` sits at 2.35 GiB/s rather than
near 4. Issue #37's bulk generation API bypasses the buffer entirely and would
expose the full 4.05 GiB/s to callers who fill spans.

**AVX2 now beats the unimplemented AVX-512 path**, which still falls through to
scalar. Issue #27's downclocking measurement should compare against 4.047 GiB/s,
not against the scalar baseline.
